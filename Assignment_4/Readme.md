1. Отличие гибридных вычислений от CPU-only или GPU-only?

В гибридных вычислениях CPU и GPU работают одновременно над разными частями задачи (как в Task 3 - 30% на CPU, 70% на GPU параллельно).

При CPU-only или GPU-only один ресурс простаивает.

 Гибридный подход позволяет использовать оба вычислительных ресурса, сокращая общее время за счёт перекрытия вычислений.

2. Для каких задач целесообразно распределять вычисления между CPU и GPU?
Целесообразно для задач с большим объёмом данных, который можно разделить (как в Task 3 - массив делится на части)

Независимыми вычислениями над частями данных (каждый элемент обрабатывается отдельно)

Достаточной вычислительной нагрузкой, чтобы overhead передачи данных окупился

например обработка изображений, матричные операции, симуляции частиц

3. Разница между синхронной и асинхронной передачей данных?

Синхронная (cudaMemcpy): CPU блокируется и ждёт завершения копирования. Следующая инструкция выполнится только после окончания передачи.
Асинхронная (cudaMemcpyAsync): CPU сразу продолжает работу, пока данные копируются в фоне. Требует CUDA streams для управления.

В Task 3 используется синхронная передача, но CPU-поток работает параллельно с GPU благодаря std::thread.

4. Почему асинхронная передача повышает производительность?

Пока GPU копирует данные → CPU может готовить следующую порцию
Пока GPU считает → можно копировать следующие данные

В Task 3 мы достигли похожего эффекта: пока GPU копирует и считает 70% данных, CPU параллельно обрабатывает 30%. гибрид быстрее GPU-only

5. Основные функции MPI для распределения и сбора данных?

MPI_Init -> Инициализация 
MPI_Comm_rank -> Получить номер процесса
MPI_Comm_size -> Получить общее число процессов
MPI_Send -> Отправить данные процессу
MPI_Recv -> Получить данные от процесса
MPI_Reduce -> Собрать и агрегировать данные (MPI_SUM)
MPI_Barrier -> Синхронизация всех процессов
MPI_Finalize -> Завершение MPI

6. Как количество процессов MPI влияет на время выполнения?

Время уменьшается с ростом числа процессов, но не линейно тк эффективность падает из-за накладных расходов на коммуникацию (MPI_Send/Recv/Reduce) и синхронизацию

7. Факторы, ограничивающие масштабируемость распределённых программ?
В целои если в архитектуре присутствует последовательная часть кода или коммуникация условно время на Send/Recv растёт с числом процессов
Также если присутствует дисбаланс нагрузки, когда части данных обрабатываются неравномерно

8. Когда распределённые вычисления оправданы, а когда неэффективны?
+++
Большие объёмы данных, не помещающиеся в память одного узла
Вычислительно тяжёлые задачи (симуляции, ML-обучение)
Задачи с высоким параллелизмом и минимальными зависимостями

---
Малые массивы 
Задачи с частыми зависимостями между данными
Когда время коммуникации сопоставимо с временем вычислений
Задачи с большой последовательной частью (закон Амдала)
